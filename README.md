# EasyKey

让手机的实体快捷键按你的习惯工作。

EasyKey 是面向指定 OPPO / 一加设备的 KernelSU 模块，可以为实体快捷键分别设置**单击、长按、双击**动作。后台使用 C 程序监听输入事件，前台通过 WebUI 管理命令和按键绑定，正常运行时保存配置即可生效。

| 项目 | 信息 |
| --- | --- |
| 当前版本 | `v3`（`versionCode=300`） |
| 作者 | MoeShadow |
| 模块 ID | `Easy_Key` |
| 后台进程 | `EasyKey` |
| 构建架构 | ARM64 / AArch64，静态链接 |
| 安装目录 | `/data/adb/modules/Easy_Key/` |

## 功能概览

- **三种手势独立绑定**：为单击、长按、双击选择不同动作，也可以将任意动作设为“未配置”。
- **WebUI 配置热更新**：保存按键绑定后，后台通过文件事件重新加载配置，无需为每次修改重启手机。
- **命令库管理**：新增、编辑、删除直接 Shell 命令或 `.sh` 脚本入口。
- **详细进程状态**：查看版本、PID、进程状态、运行时长、累计 CPU 时间、PSS / RSS 内存、线程数和输入设备。
- **常用动作预设**：提供扫码、小布功能、相机、截屏和手电筒等命令。
- **升级保留配置**：安装脚本会从旧模块复制按键配置和用户命令库。
- **主题切换**：WebUI 提供淡绿、淡紫、淡粉、白色四种主题颜色。

## 设备与使用要求

### 安装脚本允许的型号

安装时读取 `ro.product.model`，转换为小写后与以下列表精确匹配：

| 型号代码 | 型号代码 | 型号代码 | 型号代码 |
| --- | --- | --- | --- |
| `plk110` | `plz110` | `cph2747` | `pkx110` |
| `plq110` | `plr110` | `plc110` | `pmb110` |

列表以 [module/customize.sh](module/customize.sh) 为准。不匹配的型号会终止安装；型号通过检查，也不代表所有系统版本都能执行全部预设命令。

### 使用前准备

1. 设备已具备 KernelSU 模块运行环境和 Root 权限。
2. 用于打开模块 WebUI 的管理器能提供 `window.ksu.exec` 接口。普通浏览器直接打开 HTML 无法读取 Root 状态或写入配置。
3. **先在系统设置中把快捷键原有功能设为“无”**，避免系统动作与 EasyKey 同时触发。
4. 设备需提供对应快捷键输入事件。当前后端固定监听键码 `735`，会在 `/dev/input/event0` 至 `/dev/input/event63` 中查找支持该键码的设备。
5. 小布、相机、截屏、手电筒等预设依赖对应的 ColorOS / OPlus 系统组件；微信和支付宝预设需要安装相应应用。

自定义命令会以模块进程的 Root 权限执行，保存前应确认命令内容及作用。

## 安装与首次使用

1. 按[构建与测试](#构建与测试)生成 `dist/EasyKey-v3.zip`。GitHub 的 **Code → Download ZIP** 下载的是源码，不能直接作为模块安装包刷入。
2. 将安装包复制到手机，通过 KernelSU 管理器的模块安装入口选择 ZIP。
3. 安装脚本会校验型号并显示说明：按**音量加**确认继续，按**音量减**退出。
4. 安装完成后重启手机，等待系统启动完成。
5. 从管理器打开 EasyKey 的 WebUI，在主页点击“刷新”，检查进程状态和输入设备。
6. 点击单击、长按或双击卡片，为对应手势选择命令，再实际按键验证。

首次安装随包提供的绑定为：

| 手势 | 默认动作 |
| --- | --- |
| 单击 | 小布识屏（全屏 OCR） |
| 长按 | 小布识屏（全屏 OCR） |
| 双击 | 开关手电筒 |

默认值来自 [module/config.ini](module/config.ini)。升级会保留原有配置，因此升级后的绑定可能与此表不同。

## WebUI 使用说明

### 主页：查看状态与绑定动作

点击“单击触发”“长按触发”或“双击触发”，在弹出的命令列表中选择动作。选择成功写入配置后会关闭弹窗并更新主页；选择“未配置”会清空该手势的命令。

状态卡在页面初始化和点击“刷新”时读取数据。它是一次状态快照，数值不会持续自动刷新。

| 字段 | 含义 |
| --- | --- |
| 模块版本 | 当前安装目录中记录的版本 |
| PID | 检测到的 EasyKey 进程 ID；存在多个进程时取第一个 |
| 进程状态 | Linux 进程状态，例如运行、休眠、已停止 |
| 运行时长 | 当前进程自启动以来的时间 |
| 累计 CPU 时间 | 进程累计使用的 CPU 时间，单位为时间，不是瞬时占用百分比 |
| PSS 内存 | 按共享比例分摊后的物理内存占用 |
| RSS 内存 | 驻留在物理内存中的进程页面大小 |
| 线程数 | 当前进程的线程数量 |
| 输入设备 | 进程已打开的 `/dev/input/event*` 路径 |

空闲时显示“休眠”通常表示进程正在等待事件。显示“运行中”只说明检测到了 PID；若输入设备为空，还需要检查是否找到目标按键。部分 `/proc` 数据不可读时，相应字段可能显示 `—`。

### 配置：维护命令库

1. 切换到底部“配置”页面，点击右下角加号新建命令。
2. 选择“直接命令”或“间接命令”，填写名称、描述和内容。
3. 点击“保存”。点击现有条目可以编辑，也可以通过删除确认框移除条目。
4. 返回主页，将新命令绑定到需要的手势。

**命令库与按键绑定分别保存。** 绑定时复制的是命令文本，并非命令 ID。修改命令库条目后，需要回到主页重新选择该命令才能更新已绑定动作；删除命令库条目也不会自动清空已有绑定。要停止某个动作，请在主页选择“未配置”。

### 设置：切换主题

在“设置”页面选择主题颜色，主题偏好保存在 WebUI 的本地存储中。

## 手势识别规则

| 手势 | 当前实现 |
| --- | --- |
| 单击 | 未配置双击时，短按松开后触发；配置了双击时，通常等待约 `350 ms` 判断是否还有第二次短按 |
| 长按 | 持续按住达到 `1000 ms` 后触发一次，松开时不会再追加单击 |
| 双击 | 两次短按的松开事件间隔在 `350 ms` 窗口内时触发，替代这次单击动作 |

时间阈值以 [src/EasyKey.c](src/EasyKey.c) 中的 `LONG_MS`、`DOUBLE_MS` 为准，目前不能通过 WebUI 或 `config.ini` 调整。若不需要双击且希望单击更快响应，可将双击设为“未配置”。

## 配置文件与自定义命令

### 按键绑定：config.ini

设备路径：`/data/adb/modules/Easy_Key/config.ini`。

文件使用简单的 `键=命令` 格式，只识别 `click`、`long`、`double` 三个键，不需要 INI 分节。例如，下面的自定义配置将单击设为手电筒、长按设为返回桌面，并关闭双击：

```ini
click=/system/bin/sh /data/adb/modules/Easy_Key/ind/torch.sh
long=input keyevent KEYCODE_HOME
double=
```

- 一项占一行，键名需准确填写，`=` 前不要添加空格。
- 值为空表示不执行动作。禁用时应保留对应键并清空值。
- 命令必须为单行，UTF-8 编码后最多 `1023` 字节；中文等字符可能占多个字节。
- 不要给整条命令额外套一层引号；参数内部按 Shell 语法保留必要引号。
- 多行逻辑应写进 `.sh` 文件，再通过脚本路径调用。
- 正常运行时，后台会监听配置写入、替换等文件事件并重新加载。

**删除键或删除配置文件不等于禁用动作。** 后端加载配置前会设置兜底值：单击为手电筒、长按为返回桌面、双击为空。缺少的键会沿用这些兜底值；它们与安装包中的默认绑定不同。

### 命令库：repo.json

设备路径：`/data/adb/modules/Easy_Key/repo.json`。文件内容是 JSON 数组，例如：

```json
[
  {
    "id": "custom_home",
    "type": "direct",
    "name": "返回桌面",
    "desc": "发送 Home 按键事件",
    "content": "input keyevent KEYCODE_HOME"
  },
  {
    "id": "custom_torch",
    "type": "indirect",
    "name": "开关手电筒",
    "desc": "调用模块内置脚本",
    "content": "torch.sh"
  }
]
```

| 字段 | 用途 |
| --- | --- |
| `id` | 条目标识，手动编辑时应保持唯一 |
| `type` | `direct` 为直接命令，`indirect` 为模块内脚本 |
| `name` | WebUI 显示的命令名称 |
| `desc` | 命令描述 |
| `content` | 单行命令文本，或 `ind/` 目录下的脚本文件名 |

`repo.default.json` 保存随模块提供的默认命令库。用户命令库不存在时，WebUI 会尝试用它初始化 `repo.json`；已有命令库解析失败时会提示错误，不会自动用默认数据覆盖。

日常修改优先使用 WebUI。手工编辑 JSON 时注意引号、逗号及转义格式。

### 直接命令与间接命令

**直接命令（Direct）**：填写一条可在设备 Root Shell 中执行的命令，例如：

```sh
input keyevent KEYCODE_HOME
```

**间接命令（Indirect）**：先把脚本放到 `/data/adb/modules/Easy_Key/ind/`，再在命令内容中填写文件名，例如 `custom.sh`。绑定后形成的命令为：

```sh
/system/bin/sh /data/adb/modules/Easy_Key/ind/custom.sh
```

脚本应使用 UTF-8、LF 换行，并能够由 Android 的 `/system/bin/sh` 执行。WebUI 管理的是脚本入口，不提供脚本文件上传或正文编辑功能。间接命令的 `1023` 字节限制包含自动添加的解释器和目录前缀。

## 升级、备份与卸载

### 升级保留范围

| 内容 | 当前安装脚本的处理 |
| --- | --- |
| `config.ini` | 旧模块中存在时复制保留 |
| `repo.json` | 旧模块中存在时复制保留 |
| `repo.default.json` | 使用新安装包中的版本 |
| 自定义 `ind/*.sh` | 未实现自动迁移，需要自行备份并恢复 |
| 对内置脚本的本地修改 | 未实现自动保留，需要自行备份 |
| 旧版 `action.sh` | 升级时清理旧模块中的该文件 |

升级前，将 `config.ini`、`repo.json` 和自行添加或修改的脚本复制到模块目录以外保存。安装新包并重启后，检查绑定是否保留，并恢复需要的自定义脚本。

由于升级保留用户命令库，新版本默认命令的变化不会自动合并到已有 `repo.json`。需要新预设时，可参考新版 `repo.default.json` 在 WebUI 中添加或修改，再重新绑定。

### 恢复配置与卸载

- 恢复自己的配置：将备份文件复制回对应位置，打开 WebUI 刷新并测试按键。
- 恢复默认命令库：备份现有数据后，用 `repo.default.json` 的内容替换 `repo.json`。这会替换命令库条目，按键绑定仍需单独调整。
- 暂停或卸载模块：通过 KernelSU 管理器禁用或卸载后重启。若要恢复系统原有快捷键功能，再到系统设置中重新选择动作。

## 构建与测试

### 准备环境

当前仓库提供 Windows / PowerShell 脚本，需要以下命令可在终端中使用：

- `git`：获取源码。
- `uv`：运行 Python 环境并提供 `ziglang` 编译工具。
- `node`：运行 WebUI JavaScript 静态检查，完整测试时需要。

构建脚本使用 `uv run --no-project --with ziglang python -m ziglang cc`，首次运行可能需要联网下载相关依赖。编译目标是 `aarch64-linux-musl`，生成静态链接的 ARM64 可执行文件。

获取源码：

```powershell
git clone https://github.com/moeskia/easykey.git
Set-Location easykey
```

### 执行命令

只构建后台程序，输出 `module/EasyKey`：

```powershell
.\scripts\build.ps1
```

运行完整自动化检查，并生成安装包：

```powershell
.\scripts\test.ps1
```

只执行构建和打包：

```powershell
.\package.ps1
```

`package.ps1` 会自动调用构建脚本，不需要预先单独编译。当前版本的输出为 `dist/EasyKey-v3.zip`，ZIP 根目录直接包含 `module.prop` 等模块文件，不包含外层 `module/` 目录。

### 自动化检查范围

`scripts/test.ps1` 当前会检查：

1. 以 `SELFTEST` 模式编译并运行手势识别与命令解析自测。
2. WebUI 内联 JavaScript 的语法和 HTML 中重复的 `id`。
3. 两份命令库能否解析为 JSON，以及仓库中的用户初始命令库与默认命令库是否一致。
4. 模块版本为 `v3`、作者为 `MoeShadow`。
5. 通过打包脚本完成 ARM64 编译，并验证 ZIP 中预期的 9 个文件条目。

成功时输出 `All tests passed`。命令库一致性检查针对源码仓库的发行默认数据，不要求手机上的用户命令库与默认库一致。

这套脚本不包含 Android 设备端 Shell 语法检查、Root WebUI 实机交互、实际按键输入、系统服务调用或截图验证。发布功能改动前，还应在目标设备确认三种手势、清空绑定、配置热更新、手电筒开关和升级保留行为。

## 运行原理

1. `service.sh` 等待系统启动完成，设置后端执行权限，清理旧的同名进程，再启动 `EasyKey`。
2. 后端扫描输入设备，找到支持键码 `735` 的设备；未找到时每秒重试。
3. 找到输入设备后加载配置，通过 `poll` 等待按键事件与手势超时，通过 `inotify` 监听配置变化。
4. 识别手势后执行对应命令。可直接解析的 `cmd`、`input`、`service`、`/system/bin/sh` 命令使用直接执行路径；含引号、管道等 Shell 语法的命令交由 `/system/bin/sh -c` 处理。
5. WebUI 通过 Root 接口读写配置；写入时先生成临时文件，再替换目标文件，减少写入过程中读到不完整内容的机会。

后台在已找到输入设备且没有待处理手势时阻塞等待事件。启动脚本不提供持续进程守护，进程退出后需要重新启动模块服务或重启设备。

## 常见问题与排查

### 安装提示不支持的设备型号

在手机终端或 `adb shell` 中运行：

```sh
getprop ro.product.model
```

将结果与支持列表对照。适配新设备需要同时确认输入键码、设备节点和系统命令接口，单纯加入型号名单不能完成适配。

### WebUI 显示“读取失败”或无法保存

确认页面是通过支持 Root 接口的模块 WebUI 入口打开，并检查模块目录是否存在、管理器是否能执行 Root 命令。普通浏览器页面缺少 `window.ksu.exec` 时无法完成这些操作。

若提示命令库解析失败，先备份并检查 `repo.json` 的 JSON 格式；不要直接覆盖尚未备份的用户数据。

### 进程“未运行”，或“运行中”但按键无反应

先确认模块已启用、手机已重启，系统快捷键动作已设为“无”，主页对应手势也已配置。随后在设备 Shell 中取得 Root 权限并检查：

```sh
su
pidof EasyKey
cat /data/adb/modules/Easy_Key/config.ini
ls -l /data/adb/modules/Easy_Key/EasyKey
getevent -lp
```

`getevent -lp` 用于查看输入设备支持的事件。若 WebUI 有 PID 但没有输入设备，可能仍在等待支持键码 `735` 的节点；进程存在不能单独证明设备已适配。

需要手动重启后台时，在已经启动完成的设备 Root Shell 中运行：

```sh
/system/bin/sh /data/adb/modules/Easy_Key/service.sh
```

启动脚本将后台标准输出和错误输出重定向到 `/dev/null`，当前没有独立日志文件。排查某条动作时，可将 `config.ini` 中对应命令复制到 Root Shell 单独执行，观察系统返回结果。

### 单击感觉有延迟

配置双击后，单击需要等待约 `350 ms` 的识别窗口。将双击设为“未配置”，短按即可在松开时触发。

### 修改或删除命令后，按键仍执行原来的动作

命令库保存的是候选动作，`config.ini` 保存的是已绑定的命令文本。编辑条目后重新绑定；删除条目后若要停用动作，将对应手势设为“未配置”。

### 手电筒、扫码或小布功能不生效

先在 Root Shell 中直接执行相关命令。扫码入口依赖应用安装及其组件；小布、相机、截屏和手电筒依赖系统接口。系统或应用升级后若接口发生变化，需要更新相应命令或脚本。

### 配置修改没有即时生效

检查保存是否成功、配置是否符合单行和字节数限制，并点击 WebUI“刷新”核对内容。若配置正确但动作仍未变化，可重启后台，再检查输入设备是否可用；配置热更新依赖文件监听正常建立。

贡献代码前运行 `scripts/test.ps1`；涉及设备或系统接口的改动，请说明已验证的机型、系统版本和验证结果。
